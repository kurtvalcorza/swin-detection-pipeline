## Conformance notes

_Requirement identifiers in these notes (for example `ST1`, `PAR3`, `DAT24`, `EVAL21`) are the NOTEBOOK_SPEC 1.1 numbering they were written against; NOTEBOOK_SPEC 2.0 renumbered its sections and the pull request that migrated this repository reports conformance against the 2.0 pre-flight checklist (§26) and report format (§30)._

- **Standalone carrier (ST1–ST6):** the primary path performs no clone, repository install, repository import, worker process or subprocess (the generator-owned install cell excepted). Section 2 carries `src/dimer_swin_detection/metrics.py` and `src/dimer_swin_detection/runtime.py` verbatim, in dependency order (each tagged `metadata.dimer.embedded_module`; the rewrites make the default weights directory working-directory-relative and drop the one package-relative import), Section 3 carries the model identity and the 1-file SHA-256 manifest inline and asserts they agree with the module before anything is fetched, and Section 1 carries the exact `tools/pins.txt` runtime pins including the PyTorch CPU index and the OpenMMLab mmcv find-links. `metadata.dimer.generated_from` records the repository, the generating revision, both module paths, their joined SHA-256, and the generator version.
- **Qualified runtime (ENV2/ENV4):** CPython 3.10 with torch 2.1.2+cpu, MMCV 2.1.0, MMEngine 0.10.7, MMDetection 3.3.0, NumPy 1.26.4, pycocotools 2.0.11. `pip` cannot pin the interpreter, so the requirement is stated in Prerequisites and asserted (`sys.version_info[:2] == (3, 10)`) in Section 4; the carried `verify_runtime_versions` fails closed on OpenMMLab version drift. Default Colab/Kaggle runtimes (Python 3.11+) are unsupported.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when a carried module, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition and trust boundary (MOD12–MOD14):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the absent checkpoint from the pinned `download.openmmlab.com` URL (the manifest's single entry; the model host is not the Hugging Face Hub and the `MODEL_REVISION` is the MMDetection `v3.3.0` release-tag commit that is the config source); `verify_snapshot` re-hashes it against the manifest **and** `MODEL_SPEC`; `from_pretrained(weights_dir=WEIGHTS_DIR)` then lets the pinned MMDetection loader deserialize the code-capable `.pth` (upstream's `mmengine` load, not `weights_only`). The notebook states that the digest proves byte identity, not publisher authenticity.
- **Role stages:** `validate_inputs` (DAT24) writes `outputs/swin_detection_task_inference_input_manifest.json` with the schema, ceilings (`MAX_PIXELS` 64,000,000; `score_threshold` 0..1; `max_detections` ≥ 1), per-input observations, verdict, and one recorded rejection finding (missing-file probe); `evaluation_report` (EVAL21) writes `outputs/swin_detection_task_inference_evaluation_report.json` — `not-measurable` on the synthetic sample (with what labelled data would make the task measurable), `sample-sanity` with `coco_box_ap` (COCO AP@[0.50:0.95], AP50, AP75 via pycocotools) and the empty-detector baseline when `USE_COCO8` is enabled.
- **Samples:** the default sample is a deterministic 640×480 synthetic scene generated in code (no download, no ground truth); its detections are sanity evidence for the input contract and forward pass, not a correctness or benchmark claim. `USE_COCO8` (off by default) fetches the public COCO8 archive from its pinned Ultralytics release URL, refuses it unless its SHA-256 equals `54c67fe9…`, extracts only the four validation images and labels member by member after path/size checks, and converts the YOLO labels with the carried `boxes_from_yolo_labels`; no split is invented or changed.
- Detection obligations: the class count (80) and request ceilings are printed before the model runs, scores are described as uncalibrated MMDetection confidences with no shipped threshold (`score_threshold` is a caller-owned output filter, 0.0 for evaluation), and exported detections keep their score ordering per image in both JSON and CSV.
- `USE_BYOD` and `USE_COCO8` default to `False` so the sample path never opens an upload dialog or downloads data.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`. The previous Notebook Specification 1.0 notebook's clean run of 2026-09-11 (COCO AP `0.707` on COCO8) is retained there as an audit trail for the replaced carrier only.
